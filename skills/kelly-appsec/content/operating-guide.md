# 用业务规则解释接口是否安全

1. 登记项目负责人、明确仓库/部署版本、环境与授权边界。网页不接收凭据。
2. 导入 OpenAPI 或手工接口 JSON。清单只说明有哪些接口，未证明权限正确。
3. 明确每个角色、租户、对象与业务状态允许什么、禁止什么；规则由业务负责人确认。
4. 对允许行为声明受控数据断言。对拒绝行为声明预期拒绝状态、禁止数据断言和正向基线。
5. 选择有限规则创建任务。本机 Agent 再核对精确 Origin、方法、路径、对象和预算后执行；不会自动扩展目标或跟随重定向。
6. 在矩阵逐项核对预期、观察结果、来源和缺口；人工填写理由后确认漏洞或正常解释。
7. 更新项目到修复版本，导入相同策略的规则并从原发现创建复测。复测不匹配原规则和基线时不能关闭问题。
8. 导出包含来源、版本、范围与覆盖限制的报告。

源码审阅是独立的真实工作路径：Agent 读取授权仓库具体版本、追踪全局认证/权限中间件到服务层和数据查询，记录文件行与推理，然后使用离线审阅导入。关键词搜索只用于找线索，不能证明漏洞、不能表示完整 SAST。

每类数据每次最多读取 50 条，网页使用“加载更多”显式翻页。页面报告只包含已加载记录；本机 report 命令显式分页导出并注明截断。原始响应留在本机受限目录，仅同步脱敏证据摘要、哈希和来源。

“完成”表示这组步骤结束。“满足规则”只覆盖该版本、身份、受控对象与显式断言；HTTP 200、403、源码关键词或未发现异常都不能单独推出整个应用安全。
