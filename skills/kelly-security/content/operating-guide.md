# 从怀疑到可复核的证据

1. 说明症状、疑似开始时间、业务角色和已知维护。
2. 添加已获授权的本机 SSH 别名，不上传密码或私钥。
3. 选择服务器和带时区的调查范围，发起检查请求。
4. 本机 Agent 核对当前会话的授权后执行固定只读配方。
5. 在检查清单中查看采集状态、脱敏证据、来源和覆盖缺口。
6. 关联登录、访问、执行、文件和持久化事件，再记录人工复核理由。
7. 导出带证据引用、覆盖与信任限制的报告。

“采集完成”不代表服务器安全。失败登录、可疑 URI、HTTP 200、高 CPU 和临时目录中的
程序都是需要结合上下文复核的线索。没有日志、没有权限和缺失可信基线时，应报告证据
不足。主机被 root 或内核级控制时，本机日志和工具也可能被篡改，需要独立来源补证。

页面不会连接 SSH 或执行处置。没有本机 Agent 时，任务保持等待。隔离、删除、杀进程、
重启、修改审计/防火墙/SSH 或轮换凭据，都需要按具体影响另行决定。

原始取证产物保存在本机受限目录。Busabase 保存任务、复核状态、脱敏摘要与哈希；未经
明确授权，不上传原始日志。页面导出只包含已加载记录；完整报告由本机 Agent 显式批量导出。
