# 验收记录

日期：2026-10-02。验收等级：🟢 完整验收（本地 Busabase 安装、原生视图和工作台）。

## 方法

- 在独立本地 Busabase 空间安装包，使用真实 HTTP/SDK 读取安装后的资源。
- 同一空间以 `--rename` 再装一份，验证不同目录的资源归属、关联和图片仍正确。
- 核对两张表、18 条记录、资料关联、4 个打包表格视图和 3 个安装后补齐的视图。
- 重复运行原生视图安装脚本，检查没有重复创建。
- 用 Playwright 打开实际安装的 AirApp，检查总览、资料、文章表格、看板、月历、
  待审核、文章详情和关联资料详情。
- 检查资料搜索、主题与状态组合筛选，以及打开原生看板的真实浏览器跳转。
- 桌面视口为 1440×900、1280×720，手机为 390×844、360×844；另检查深色主题。
- 运行 scoped TypeScript 检查、AirApp 检查和 5 个领域测试；检查模板格式和封面。
- 从安装后的原生页面重新跑一遍浏览器故事，截取总览、资料搜索、文章看板、
  待审核、关联资料和原生看板，并将证据上传到公开 CDN 后逐个确认返回 200。

## 结果

- 8 份资料、10 篇文章；3 篇待审核、2 份待核对，状态分组为 2/2/3/1/2。
- 搜索 PDF 命中一份资料；状态筛选命中三篇待审核文章，与主题组合后剩一篇。
- 一份资料可供多篇文章使用，一篇文章可以打开多个关联资料。
- 月份切换不会修改排期；原生表格、看板、日历读取同一批记录。
- 浏览器没有脚本错误，各视口没有页面横向溢出；手机表格转为逐条展示。
- 发现固定 `3000` 端口会与同机其他运行实例冲突，已改为由本地运行器分配空闲端口；
  修正后再次从原生页面启动并检查实际数据。
- 原生视图的创建脚本重复运行不增加视图。
- 第二份安装依然有 8 份资料、10 篇文章、完整关联和 8 张可下载截图；
  它的工作台从新目录读取数据，浏览器没有脚本错误。

- 仓库级 TypeScript 检查在改动前后均为同样的 130 条既有错误；本包独立检查通过，

## 已知限制

- 本地当前版本已验证；Cloud 和 browser runtime 没有验收，不能推断为全平台可用。
  AirApp 明确优先使用本地 Node 引擎。
- 当前 `busabase-package@1` 只能打包表格视图，原生画廊、看板、日历需按 Skill
  运行一次限定安装脚本；AirApp 内的看板、日历可直接读取安装数据。
- 同一空间已有本模板时，第二次安装要显式使用 `--rename`；否则全空间节点 slug
  冲突，安装器会拒绝，不会无声覆盖旧实例。
- 发布的部分旧版本地服务缺少节点自定义提示词接口。当前本地服务读回成功；
  如安装器返回相关警告，应先升级服务，不能把警告当作提示词已保存。
- 包不携带记录附件值，截图安装在 Drive；不声称附件字段已经绑定这些图片。
- 列表搜索与筛选只覆盖已加载记录，单批上限 50 条；后续批次需显式翻页。
- 工作台只读，编辑、状态修改和审核使用 Busabase 原生界面；未接入公众号发布。
- 仓库全量 TypeScript 检查仍有 130 条与本模板无关的旧错误；原始提交作同环境基线
  也为 130 条，且错误集合相同。这不等于全仓 typecheck 已经通过。
