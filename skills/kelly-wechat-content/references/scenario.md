# 示例故事与验收

## 故事

一个三人编辑团队要把零散资料变成下一周公众号选题。资料长期复用，文章单独走写作、
审核和排期；审核者需要发现来源未核对、负责人缺失和还不能发布的稿件。

## 必须能看到

1. 总览显示本周工作、待审核文章与需要补信息的稿件。
2. 资料库可按主题与核对情况筛选；选择资料能看到摘要、原文和被哪些文章使用。
3. 文章表格和看板显示相同记录，状态、负责人和关联资料一致。
4. 发布日历把同一篇文章放在计划日期，切换月份不会改数据。
5. 待审核视图显示三篇稿件，其中至少一篇需要替换演示来源。
6. 文章详情打开关联资料后，可以回到文章列表和原来视图。
7. Native Busabase 的两张表也包含同样的记录、关联和表格/看板/日历视图。

## 演示与安装的一致性

`content/sources/records.ndjson` 和 `content/articles/records.ndjson` 是演示样本来源。
Demo provider 由它们生成，安装时同一组记录进入新空间，资料关系按 package-local key 转换。
浏览器 Demo 是明确的只读选择；实际连接模式不读取 Demo 作为替代数据库。

图库只用真实运行截图。封面最后从已验收截图生成，排在 manifest 首位。
素材文件放在可安装的 Drive 中，不能把 record 附件的临时空间 ID 写进模板。

## 公开动作

本模板不连接公众号账户，没有自动发布能力。Agent 提供草稿和排期建议，人通过原生
变更请求审核；真正对外发布或把截图发到论坛必须另获明确授权。
