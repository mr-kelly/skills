# 裁判规则

当前版本：v2

裁判是真实天气：遛狗那个钟点，到底下没下雨。
Agent 能不能自己进化，不看它多聪明，看这份规则靠不靠得住。
这份文档对 Agent 只读。Agent 觉得规则有问题，只能写建议，由主人来改。

## 怎么判一天

每天只判 Agent 选的那一个钟点。实际天气用 Open-Meteo 的历史数据（archive）。

- 淋雨：那个钟点的实际降水 ≥ 0.2 mm。
- 太热：那个钟点的实际气温 ≥ 32°C，狗爪会烫。
- 不方便：那个钟点不在主人的方便时段里。主人方便的是早上 7 点、8 点，傍晚 5 点到晚上 9 点。
- 三样都没有：没淋。

「每天的决定」里一天只写一个结论：先看淋没淋，再看热不热，再看方不方便。
数次数时三样分开数，一天可以既淋雨又太热。

## 怎么打分

- 主指标：淋雨次数，越少越好。
- 护栏：太热 0 次、不方便 0 次。护栏先看：新手册超出护栏的次数不许比旧手册多；超出得更少，就算进步，哪怕淋雨多了几次。护栏一样时，再比淋雨。
- 证据门槛：新规则必须换一个月也赢；每次都在同一个月和旧手册对照。只认回放算出来的数，不认网页上的说法。

## 阈值

脚本从这一块读阈值，不在代码里写死。改了这里，裁判就变了。

```裁判规则
版本: v2
淋雨: 实际降水 ≥ 0.2 mm
太热: 实际气温 ≥ 32°C
主人方便时段: 7, 8, 17, 18, 19, 20, 21
主指标: 淋雨次数
护栏: 太热 0 次, 不方便 0 次
证据门槛: 换一个月也要赢; 同一个月和旧手册对照
```

## 为什么从 v1 改成 v2

v1 只数淋雨。7 月 Agent 提议「方便时段放开到全天」，同月回放淋雨 5 → 0，主人只看了淋雨就合并了。
8 月这条规则只淋了 2 次雨，却有 14 天遛在主人上班的时候、5 天在正午烫脚——v1 一样都没数。
规则没有错，是裁判只看了一个数。所以主人亲手加了护栏和证据门槛。
